# Management interface

`/admin/boards` is an authenticated view for the signed-in user's boards; the shared app library lives in a separate authenticated view at `/admin/apps`. Account settings live at `/admin/account`. These views must work on narrow screens and with keyboard navigation. A shared sticky menubar, matching the board view, links the views with icon-labelled Boards and Apps items, offers a Create app plus button with a tooltip, and includes the signed-in user menu. The menu trigger shows a person icon and the user's display name; it links to Account (`/admin/account`) and Manage (`/admin/boards`) and offers Sign out. The `/admin/boards`, `/admin/apps`, and `/admin/account` views set the browser title to `Shelf · Boards`, `Shelf · Apps`, and `Shelf · Account`. It must remain usable when the display name is long or the screen is narrow. Creating or editing a board or app opens an accessible modal dialog, and destructive actions ask for confirmation before proceeding. `/admin/boards` is the destination after first-account setup. Older `/admin` and `/account` URLs redirect to their new locations.

Admin navigation and content use the same maximum width as public board views.

## Shared app library

The shared navigation's green Create app action is available on signed-in pages, including board views. Outside a board, creation may optionally select an owned board and category to create and assign together. From a managed board, the form offers a checked-by-default option to add to the current board and a category selector. Board and category choices update when boards or categories are created, changed, or deleted. If app creation succeeds but assignment fails, the form reports partial success and retries only assignment for the saved app.

Modal headers and action footers stay visible as long forms scroll. When no shared apps remain available to add to a board, add-app dialogs show a “No apps left to add” placeholder below the filter.

- List app names, descriptions when present, URLs, and saved icons in a single-column list with a filter, plus each app's last recorded liveness state, check time, and failure reason when present.
- Keep each app in one compact row with its icon, name, description and URL, and a trailing action-menu trigger on the same line. Show the URL below the title in smaller secondary text with an external-link icon; it opens in a new tab. Overlay the status dot on the icon's top-right corner. The menu contains “Check now” for that app, Add to board, Edit, and Delete; it must work with touch and keyboard input without crowding narrow screens. Keep the previous status visible while a check runs, show progress and any request error without adding a second row to the app card, and update the status when the check completes. See [app-status.md](app-status.md) for probe and cache behavior.
- Add an app to a board directly from the library: choose a board that does not already have the app, optionally a category on that board, and confirm. The board must be one the signed-in user owns.
- Create an app with name, optional plain-text description of up to 280 characters, URL, and explicit icon search/selection.
- Edit name, description, URL, or icon. Deleting prompts for confirmation that the app disappears from every board.
- Import apps from an existing Homarr instance through the two-step wizard described in [homarr-import.md](homarr-import.md).
- Every signed-in user sees and can manage the same library.

## My boards

- `/admin/boards` lists only boards owned by the signed-in user in a single column on narrow screens and two columns from the `md` breakpoint. It identifies the default board with a ghost icon-only Set as default control to the left of each title, with a “Set as default” tooltip. Fill the default star yellow and leave other stars neutral. Clicking anywhere else on a board row opens its edit page at `/admin/boards/<nanoid>`; do not display the URL path or an Edit button. Show a decorative edit icon on card hover for mouse devices and always on touch devices; the icon has no separate hover or click behavior.
- Create boards from `/admin/boards`. On `/admin/boards/<nanoid>`, show the linked board title and a ghost icon-only Set as default control to its left, with a “Set as default” tooltip. Place Rename, Add category, and Delete on the right side of the header. Deleting a board requires confirmation. Disable Set as default for the current default board. The board content contains only the categorized app lists, with no outer border or “Apps” heading; each category group has a thin border, no inner padding, and a distinct background container separated by physical space. Keep the category heading background. App rows have no gap between them and use a subtle hover background.
- For each board, add apps from the shared library through a filterable add-app dialog, remove assignments, and reorder them with touch-capable drag and drop within and between categories, including into empty groups. Keep the dragged app attached to the pointer or touch, and show an insertion line at the selected boundary before, between, or after apps. Use the same insertion slot for the preview and drop without adding visible space to the list. Keep the category selector for manual cross-category moves. Place the add-app control in the “Uncategorised” section header, including when the board has no categories; do not show a separate board-level add-app control. Each assigned app row shows its name and full app URL, including protocol; the URL is a smaller secondary link with an external-link icon and opens the app in a new tab. Keep category Move up / Move down controls.
- For each board, create, edit, reorder, and delete categories. Always show an “Uncategorised” section, including when it is empty or the board has no categories. An info popover beside that heading, styled like the public board popovers, explains that these apps appear first without a category on the public board. Assign apps to one category or leave them uncategorized; drag and drop reorders apps within groups and moves them between groups, while Move up / Move down controls reorder categories. The “Uncategorised” header's add-app control assigns no category, and each category header's control assigns that category; their dialogs do not show a category selector. Deleting a category moves its apps to the end of the uncategorized group; see [categories.md](categories.md).
- Creation of a user's first board sets it as default. When a user owns no board, show a clear create-board empty state.
- Changes persist immediately and the affected board view reflects them on its next load. Failed operations show an actionable error without falsely displaying success.

The admin page does not offer editing controls for another user's board.
